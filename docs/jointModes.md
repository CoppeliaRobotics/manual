# Joint modes

A joint can be in one of the following 3 modes:

- **Kinematic mode**: the joint operates in kinematic mode and is not handled by the [dynamics module](dynamicsModule.md). It can instantaneously change its linear/angular position (e.g. via [`joint.joint.position`](sim-2/property_joint_joint_position.md), [`joint.joint.quaternion`](sim-2/property_joint_joint_quaternion.md) or [`joint.configuration`](sim-2/property_joint_configuration.md)), feature a specific motion profile (via [`joint.targetPosition`](sim-2/property_joint_targetPosition.md), [`joint.targetVelocity`](sim-2/property_joint_targetVelocity.md) and [`joint.maxVelAccelJerk`](sim-2/property_joint_maxVelAccelJerk.md)), or be handled in a customized manner via a [joint callback function](jointCallbackFunctions.md)
- **Dependent mode**: the joint is directly dependent of another joint via a linear equation. The joint is not handled by the [dynamics module](dynamicsModule.md)
- **Dynamic mode**: the joint is handled by the [dynamics module](dynamicsModule.md), if it forms with its connecting items a valid configuration, i.e. is [dynamically enabled](designingDynamicSimulations.md#dynamicallyEnabled). In that case, it can be [controlled in various modes](jointDynamicsProperties.md). Refer also to [`joint.targetPosition`](sim-2/property_joint_targetPosition.md), [`joint.targetVelocity`](sim-2/property_joint_targetVelocity.md) and [`joint.maxVelAccelJerk`](sim-2/property_joint_maxVelAccelJerk.md).

There are many different ways a joint can be controlled, depending on its joint mode and control mode, but you can differentiate between [high-level control](#high) and [low-level control](#low):

<a id="high"></a> **High-level control** is achieved mainly via specific properties and methods, such as [`joint.joint.position`](sim-2/property_joint_joint_position.md) [`sim.setJointPosition`](sim-1/simSetJointPosition.md), [`joint.targetPosition`](sim-2/property_joint_targetPosition.md) [`sim.setJointTargetPosition`](sim-1/simSetJointTargetPosition.md), [`joint.targetVelocity`](sim-2/property_joint_targetVelocity.md), [`joint.dynamics.targetForce`](sim-2/property_joint_dynamics_targetForce.md), [`joint.setTargetPosition`](sim-2/joint_setTargetPosition.md) or [`joint:setTargetVelocity`](sim-2/joint_setTargetVelocity.md).

<a id="low"></a> **Low-level control** is best implemented via a [joint callback function](jointCallbackFunctions.md) from within CoppeliaSim. In that case the joint should be in kinematic mode, or in dynamic mode. The callback function is then constantly called by CoppeliaSim, to fetch new regulation values.

[Joint callback functions](jointCallbackFunctions.md) are ideal for low-level control of a joint, since the controller will *regulate* the joint in each time step, i.e. skipping a regulation step for a low-level controller is not an option. For joints in kinematic mode the regulation time step is the same as the simulation time step (50 ms by default). Joints in dynamic mode on the other hand will use a much finer regulation time step as defined by the dynamics module (5 ms by default).

In case of an external application wanting to perform low-level control of a joint, joint callback functions are not available, and so the external application should make sure that it will run synchronously with CoppeliaSim. This happens via the [stepping mode](simulation.md#stepped), where the external application is in charge of explicitly triggering each simulation step. Additionally, for a fine-grained control, the simulation time step should be the same as the dynamics module time step.
